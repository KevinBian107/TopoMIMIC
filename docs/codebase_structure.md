# TopoVNL Codebase Structure

A comprehensive guide to understanding the organization of the TopoVNL project for topological analysis of behavioral latent spaces.

---

## Project Overview

TopoVNL (Topological Virtual Neuroscience Lab) analyzes deep reinforcement learning latent spaces through computational topology. The project uses discrete Morse theory and persistent homology to extract interpretable structure from behavioral manifolds generated by the Mimic-MJX package.

```
                        TopoVNL Project
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│    ┌──────────────┐    ┌──────────────┐    ┌──────────────┐    │
│    │  Mimic-MJX   │───▶│   TopoVNL    │───▶│   Analysis   │    │
│    │   Rollouts   │    │   Pipeline   │    │   Results    │    │
│    └──────────────┘    └──────────────┘    └──────────────┘    │
│                                                                 │
│    Input Data          TDA Processing      Visualization &      │
│    (latents,qpos)     (DM,W2,Cluster)     Interpretation       │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

Figure 1: High-level data flow from Mimic-MJX simulation outputs through
topological analysis to behavioral clustering results.
```

This subproject provides the C++ implementation for discrete Morse graph reconstruction.

### Architecture

```

│   ├── __init__.py
│   │
│   ├── pcd/

│   └── baseline/
│       └── __init__.py              # Density-based baseline

│           └── compute_graph_reconstruction_baseline()
│
└── code/
    ├── persistence_swr/

    │   ├── spt_cpp                  # Compiled executable
    │   └── phat/                    # PHAT library
    │
    ├── phat_morse_src/
    │   ├── ComputeGraphReconstruction.cpp

    ├── persistence_baseline/        # Baseline persistence
    └── baseline_morse_src/          # Baseline reconstruction

Figure 5: The dmpcd package wraps C++ executables for efficient
```

### Compiled Executables Required

The C++ components must be compiled before use:

1. **persistence_swr/spt_cpp** - Computes persistence of sparse weighted Rips filtration
2. **phat_morse_src/a.out** - Performs discrete Morse graph reconstruction

### Configuration Hierarchy

**dm_pipeline_{space}.yaml** defines:
- `data.dm_key`: Feature space key ("intention", "qpos", or "ekp")
- `data.rodent_rollout_dir`: Path to rollout data
- `takens.m`: Embedding dimension (typically 3)
- `takens.tau`: Time delay (varies by feature space: 6 for intention, 8 for ekp)
- `dm.pers_delta`: Persistence threshold (varies by feature space)
- `dm.k_neighbors`: kNN for density weights
- `dm.use_dm_path`: Enable DM path extraction (H0 paths between density minima)

**experiment.yaml** defines:
- `dm.results_dir`: Path to DM pipeline output
- `clustering.target_len`: Uniform sampling length
- `clustering.only_max`: Whether to keep only longest cycle
- `k_selection.n_clusters`: Number of clusters
- `methods`: List of enabled clustering methods
- `seeds`: Random seeds for reproducibility

## Method Registry

### Available Methods

| Method | Description | Distance Type |
|--------|-------------|---------------|
| `w2_dmc_int_kmeans` | W2 on DM cycles (intention) → MDS → KMeans | Wasserstein-2 |
| `w2_dmc_qpos_kmeans` | W2 on DM cycles (qpos) → MDS → KMeans | Wasserstein-2 |
| `w2_dmc_ekp_kmeans` | W2 on DM cycles (ekp) → MDS → KMeans | Wasserstein-2 |
| `w2_dmp_int_kmeans` | W2 on DM paths (intention) → MDS → KMeans | Wasserstein-2 |
| `w2_dmp_qpos_kmeans` | W2 on DM paths (qpos) → MDS → KMeans | Wasserstein-2 |
| `w2_dmp_ekp_kmeans` | W2 on DM paths (ekp) → MDS → KMeans | Wasserstein-2 |
| `w2_full_kmeans` | W2 on uniform frames (baseline) → MDS → KMeans | Wasserstein-2 |
| `gw_dmc_int_kmeans` | GW on DM cycles (intention) → MDS → KMeans | Gromov-Wasserstein |
| `kpms_intention` | KPMS state-space (AR-HMM or SLDS) | State-space |

Method naming convention: `{distance}_{source}_{feature_space}_{algorithm}` where:
- distance: `w2` (Wasserstein-2), `gw` (Gromov-Wasserstein)
- source: `dmc` (DM cycles, H1), `dmp` (DM paths, H0), `full` (uniform baseline)
- feature_space: `int` (intention), `qpos`, `ekp` (egocentric keypoints)
- algorithm: `kmeans`

## Key Dataclasses

### Configuration Dataclasses

**PipelineConfig** (dm_pipeline.py):
- `output_dir`: Output directory path
- `data`: DataConfig with source paths
- `takens`: TakensConfig with $m$ and $\tau$
- `dm`: DMConfig with persistence parameters
- `rendering`: RenderingConfig for video output

**ExperimentConfig** (experiment.py):
- `output_dir`: Output directory path
- `rodent_rollout_dir`: Data source path
- `split`: Data split ("train", "test", "all")
- `clustering`: ClusteringConfig with window parameters
- `k_selection`: KSelectionConfig with cluster count
- `seeds`: List of random seeds
- `methods`: List of MethodEntry objects

**ClusteringResult** (methods.py):
- `labels`: Cluster assignment array
- `n_clusters`: Number of clusters found
- `method_name`: Name of clustering method
- `seed`: Random seed used
- `extra`: Additional method-specific data

## Quick Reference: Running the Pipeline

**Step 1: Run DM Extraction** (per feature space, or use automation script)
```bash
python -m topo_mimic.dmwk.dm_pipeline configs/dmwk/dm_pipeline_intention.yaml
python -m topo_mimic.dmwk.dm_pipeline configs/dmwk/dm_pipeline_qpos.yaml
python -m topo_mimic.dmwk.dm_pipeline configs/dmwk/dm_pipeline_ekp.yaml
# Or: bash bash_scripts/run_dm_pipeline.sh
```

**Step 2: Run Benchmark Experiments**
```bash
python -m topo_mimic.benchmark.experiment configs/benchmark/experiment.yaml
# Or: bash bash_scripts/run_benchmark.sh
```

**Step 3: Run Analysis**
```bash
python -m topo_mimic.benchmark.analysis.main configs/benchmark/analysis.yaml
```

**Step 4: Run Granularity Analysis** (Optional)
```bash
python -m topo_mimic.granularity.main configs/dmwk/granularity.yaml
# Or: bash bash_scripts/run_granularity.sh
```
